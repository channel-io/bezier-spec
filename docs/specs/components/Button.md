# Button

| 항목           | 값                                                 |
| -------------- | -------------------------------------------------- |
| 공개 명세 버전 | 0.1.0                                              |
| 상태           | 검토 초안                                          |
| 적용 범위      | 공통 액션 설계 규칙. API·치수는 플랫폼 문서에 정의 |
| 확인한 구현    | Web @channel.io/bezier-react@4.0.0-next.15 /beta   |

텍스트 레이블로 저장·제출·상태 변경 등 하나의 액션을 실행하는 컴포넌트다.

## 선택 기준

- 화면의 주 액션에는 가장 높은 시각적 위계를 준다. 보조 액션은 outlined 또는 ghost 수준으로 낮춘다.
- 콘텐츠 위에 떠 있는 도구에는 floating 스타일을 고려한다. 이미 그림자가 있는 카드·패널 내부에서는 그림자가 중첩되지 않게 한다.
- 페이지 이동이 목적이면 링크 의미를 제공한다. Web의 구체적인 렌더링 방법은 [Web Button](../platforms/web/Button.md)을 따른다.
- 아이콘만 필요한 액션에는 [IconButton](IconButton.md)을 사용한다. 빈 레이블로 Button을 우회하지 않는다.

액션 위계·의미·로딩 표시의 공통 기준은 [액션과 피드백](../foundations/action-and-feedback.md)을 따른다.

## 레이블과 아이콘

- 결과를 나타내는 짧은 동사를 쓴다. 예: 저장, 초대하기, 내보내기.
- 되돌릴 수 없는 액션은 목적어를 포함한다. 예: 채널 삭제, 연결 끊기.
- ‘여기 클릭’처럼 맥락이 사라지면 의미를 알 수 없는 레이블을 피한다.
- 아이콘은 텍스트의 의미를 보완한다. 방향을 나타내는 아이콘은 앞에, 메뉴를 여는 화살표는 뒤에 배치할 수 있다.

## 상태와 접근성

기본·비활성·처리 중 상태를 구분한다. 요청 대기 중에는 처리 중임을 알리고 중복 실행을 막는다. 이것이 제공된 컴포넌트의 자동 타이머나 업무 로직까지 보장한다는 뜻은 아니다.

키보드로 조작할 수 있고 포커스를 식별할 수 있어야 한다. 플랫폼별 입력 방식·API·치수·토큰은 해당 구현을 확인한 문서에서 읽는다.

## 플랫폼별 연결

- [Web Button](../platforms/web/Button.md): label·variant·semantic·size와 상태 동작
- [iOS](../platforms/ios/README.md), [Android](../platforms/android/README.md): 구현 대조 전. Web prop 이름이나 치수를 그대로 사용하지 않는다.
